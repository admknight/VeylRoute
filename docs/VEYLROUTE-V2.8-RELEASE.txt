OBSERVED ON WINDOWS
The v2.7 component download displayed 'Background worker did not complete' and both
Wintun/tun2socks remained Missing. No signed or checksum-verified component install
has been demonstrated. The original underlying Windows exception was obscured.

SOURCE-CONFIRMED FAILURE PATH
v2.7 checks for running Tor-related processes before initializing telemetry. A
safety-blocked operation can therefore exit without a progress record, hiding its
real exception behind an unreliable generic message. This is a confirmed source
flaw; whether it caused the user's particular failure is not yet established.

CHANGES
- Begin helper-operation telemetry before checking for running processes.
- Name a conflicting process and its PID; preserve the safety restriction.
- Capture child PowerShell stderr in last-result.json and the themed error dialog.
- Include actual failing stage/exception in the error dialog with targeted advice.
- A failed progress-record replace uses bounded retries and a controlled fallback
  for non-security-critical telemetry; cryptographic gates remain unchanged.
- A transfer failure cannot be presented as installed or verified.
- Preserve Engine v3.5.1 scripts, Tor/Wintun binaries (not included), settings,
  configuration format, bridge data (blank in fresh ZIP), and security policies.
